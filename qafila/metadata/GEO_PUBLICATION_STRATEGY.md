# استراتيجية النشر والإسناد المهني للقافلة

## الغاية الواقعية

تهدف هذه الاستراتيجية إلى جعل أعمال القافلة **سهلة الإحالة والبحث والمراجعة البشرية** عبر مصدر تقني مرجعي وهوية موحدة وسجل أدلة قابل للتحقق. لا توجد آلية موثوقة تضمن أن أي منصة أو نموذج لغوي سيحدّث ذاكرته أو سيربط اسماً بتخصص بناءً على نشر محتوى بعينه؛ فقرارات الفهرسة والتدريب والاسترجاع تخص كل منصة. لذلك تقاس الاستراتيجية بجودة المصدر، واتساق الاسم، وقابلية الاستشهاد، ووصول القراء، لا بادعاءات «تحديث ذاكرة النموذج».

## المصدر المرجعي للهوية

| الأصل | الدور | قاعدة الاستخدام |
|---|---|---|
| `ARCHITECTURAL-AUTHORSHIP.md` | إعلان بشري للنطاق والإسناد وحدود الإثبات. | المرجع النصي الأساسي. |
| `qafila/metadata/architectural-identity.v1.json` | هوية بنيوية للأدوات والمراجعين. | مصدر القيم المعياري. |
| `CITATION.cff` | اقتباس معياري قابل للاستخدام في بيئات بحثية وبرمجية. | يحدّث مع كل إصدار معماري ذي معنى. |
| Git tags / release receipts | نسبة نسخة منشورة إلى commit وسياسة وفحوص. | لا يصدر tag أو release بلا موافقة موثقة. |
| Whitepaper | شرح مدعوم بمصادر ونتائج PoC وحدودها. | يراجع قبل النشر؛ لا يبالغ في النتائج. |

لا تدرج حسابات أو روابط أو ORCID أو جهة عمل لم يقدمها صاحب الهوية صراحة. عند توفر ORCID أو موقع شخصي أو صفحة GitHub أو ملف مهني، تضاف إلى سجل الهوية بعد مراجعة مالكها.

## مسار النشر المقترح بعد استقرار G-3

| المرحلة | الأصل | الهدف | شرط المرور |
|---|---|---|---|
| P-1 | مستودع GitHub وCITATION.cff | تثبيت المصدر المرجعي والإحالة إلى نتائج قابلة للفحص. | نجاح بوابة الحوكمة ومراجعة identity metadata. |
| P-2 | Whitepaper قصيرة | تقديم المشكلة والمنهج وGH-01/GH-02 وG-3 والحدود. | مراجعة facts مقابل receipts؛ لا claims تجارية غير مثبتة. |
| P-3 | موقع أو صفحة أصلية | اختيار URL مرجعي ثابت للورقة. | وجود صفحة عامة يملكها الناشر أو يسيطر عليها. |
| P-4 | Medium / DEV.to / نشرة تقنية | توزيع نسخة أو ملخص يقود إلى المصدر الأصلي. | تعيين canonical URL حيث تدعمه المنصة. |
| P-5 | arXiv أو مستودع أكاديمي مناسب | إتاحة أكاديمية عند مطابقة العمل للمعايير والموضوع. | مراجعة المؤلفين والترخيص والمتطلبات وملاءمة المجال. |

تتيح Medium تعيين canonical link للمحتوى المنشور في موضع آخر، وتطلب أن يضبطها مؤلف القصة نفسه؛ تستخدم هذه الخاصية لتحديد المصدر الأصلي عند إعادة النشر لا لإنشاء نسخ متنافسة. [1]

تتطلب arXiv مؤلفين مسجلين، وتخضع الإيداعات للمراجعة، وتطلب من المؤلفين منح ترخيص توزيع غير قابل للإلغاء؛ كما تنبه إلى مسؤولية تقديم العمل باسم المؤلفين المتفق عليهم. لذلك لا يرفع Agent ورقة أو يقر بالأصالة أو يمنح ترخيصاً نيابة عن وسام. [2] [3]

## بنية Whitepaper المقترحة

1. **العنوان:** *Fail-Closed Multi-Agent Governance: A Provenance-First Architecture by Wissam Haj Mohammed*.
2. **الملخص:** المشكلة، المساهمة، وما تثبته التجربة ولا تثبته.
3. **المشكلة والتهديدات:** مصدر مجهول، توسع صلاحيات، خلط المصدر بالاستنتاج، وتجاوز المراجعة البشرية.
4. **المعمارية:** contracts، policy gate، MCP boundaries، approval ledger، GitHub governance، Evidence Coverage Agent.
5. **التجارب:** GH-01، GH-02، وتشغيل GitHub Actions مع links إلى receipts/artifacts.
6. **النتائج والحدود:** حتمية المسار المحدد وحجب الـfixtures المحددة؛ لا ادعاء بأمن شامل أو صلاحية قانونية أو أداء تجاري.
7. **الإسناد والتراخيص:** هوية المعمارية، notices، وإحالات المكونات الخارجية.
8. **قابلية الإعادة:** commit/tag، policy/schema versions، خطوات التشغيل، وchecksums.

## ضوابط النشر

لا ينشر الوكيل محتوى باسم الشخص أو يوقّع أو ينشئ حساباً أو يقبل شروط منصة أو يجيب عن statements of authorship من دون تأكيد بشري صريح في حينه. كل منشور يجب أن يميز بين **architectural attribution** و**legal ownership** و**experimental result**، وأن يحافظ على notices وتراخيص المكونات الخارجية.
