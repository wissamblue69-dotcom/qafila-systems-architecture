# Qafila Shared Git Coordination Ledger

## الغرض

هذا المسار هو السجل المرجعي للتنسيق القابل للمراجعة بين المراجعين والوكلاء. لا يتصل أي وكيل بآخر اتصالاً صامتاً عبره، ولا يمثل وجود ملف قراراً تنفيذياً. كل ملف يجب أن يرتبط بالـcommit الذي احتواه وبسجل إيصال أو مصدر يحدد نطاقه.

## المسارات

| المسار | الغرض | صلاحية المعنى |
|---|---|---|
| `review_capsules/` | مراجعات من وكلاء أو مراجعين خارجيين، تحفظ كـsource records. | review candidate فقط، لا تحويل تلقائي إلى policy أو تنفيذ. |
| `receipts/` | `context_run_receipt.json` وسجلات البصمات. | دليل على المحتوى ومسار التشغيل، لا حكم قانوني أو موافقة بشرية. |
| `verification/` | أسئلة تحقق وعقود قبول ونتائجها عند تشغيلها. | يثبت اكتمال إجابة محددة فقط، لا هوية المجيب ولا صلاحية تنفيذ. |

## قواعد الإدراج

كل إدخال مراجعة يجب أن يذكر مصدره، وتاريخه، ونطاقه، والـcommit أو blob hash عند توفره. لا يدخل secret أو token أو محتوى خاص كامل في هذا المسار. أي ملف يطلب تغييراً خارجياً يجب أن يضم `approval_id` صالحاً أو يصنف `proposal`/`hold`.

## اختبار التحقق الحالي

يوجد `verification/verification_test.v1.json` كسؤال حتمي حول GH-02 وتثبيت إصدارات Actions. حتى تُسجل إجابة مستقلة وتطابق مع قاعدة القبول، يبقى وضع الاختبار `defined_not_executed`؛ لا تُعامل العبارة المتوقعة أو مراجعة Gemini المسجلة كإثبات هوية أو موافقة.

## التكامل مع GitHub

بعد دفع الفرع وفتح Draft PR بموافقة بشرية، يقرأ كل مراجع هذا المسار كجزء من تغيير مرئي قابل للتعليق. لا يصبح أي check أو branch protection إلزامياً حتى تعمل workflow باسم check النهائي في GitHub، وتتم مراجعة نتائجها.
