# خطة عمل GitHub والحوكمة الموازية لمشروع القافله

**الحالة:** خطة مستقلة قيد الاعتماد التنفيذي.

**المالك وصاحب القرار النهائي:** المهندس وسام جمال حاج محمد.

**الغرض:** تشغيل مسار GitHub والحوكمة كمسار موازٍ ومستقل عن إنتاج الأصول الإبداعية، مع اعتباره طبقة تشغيل إلزامية لكل ما يتعلق بالكود، الحسابات، الصلاحيات، الأتمتة، وسير العمل التجاري.

> **المبدأ:** الإبداع لا يُقيد بطبقة الحوكمة أثناء التوليد، لكن أي كود أو حساب أو أتمتة أو أصل يدخل في مسار تجاري يمر عبر بوابة الحوكمة قبل التشغيل أو النشر أو تحقيق الإيراد.

## 1. نطاق المسار

يشمل هذا المسار مستودعات GitHub، الفروع، Pull Requests، Actions، الإصدارات، الحسابات المرتبطة، الأسرار والصلاحيات، سجلات Provenance، الموافقات البشرية، أتمتة التسويق والتأهيل، مسارات الدفع أو الشراكات، وواجهات الربط بين الأصول الإبداعية والطبقة التجارية.

ولا يشمل فرض أسلوب إبداعي، أو تقييم جودة الفكرة أثناء التوليد، أو منع التجريب الفني، ما دام التجريب لا ينفذ فعلًا خارجيًا ولا يكشف سرًا ولا يعلن ادعاءً تجاريًا.

## 2. المخرجات المستقلة المطلوبة

| المعرف | المخرج | الغرض | معيار القبول |
|---|---|---|---|
| GH-GOV-01 | سجل المستودعات والحسابات | ربط كل مستودع وحساب بدوره ومالكه وبيئته | لا مورد بلا مالك وحالة وصلاحية واضحة |
| GH-GOV-02 | سياسة الفروع وPull Requests | فصل التجربة عن المراجعة وعن الإصدار | كل تغيير قابل للتتبع عبر فرع وPR أو سجل استثناء |
| GH-GOV-03 | بوابة Deterministic Gate | فحص Schema وProvenance وFail-Closed | الفشل يحجز التغيير قبل أي نشر |
| GH-GOV-04 | سجل الموافقات | ربط الفعل الخارجي بموافقة دقيقة ومؤقتة | approval_id والهدف والنطاق والسياسة والإيصال متطابقة |
| GH-GOV-05 | سجل الأسرار والصلاحيات | تقليل صلاحيات الحسابات والأدوات | لا سر داخل الكود، ولا صلاحية أوسع من المهمة |
| GH-GOV-06 | سجل الإصدارات والإيصالات | إثبات ما نُفذ ومتى وبأي نسخة سياسة | كل إصدار أو تشغيل ينتج receipt قابلًا للمراجعة |
| GH-GOV-07 | سجل الأتمتة التجارية | توثيق كل مهمة آلية وحدودها ومخرجاتها | الوضع الافتراضي draft-only وdry_run |
| GH-GOV-08 | بوابة ربط الأصول الإبداعية | تحويل الأصل الإبداعي إلى أصل قابل للتسويق وفق موافقة | المصدر والحقوق والمسار التجاري موثقة |

## 3. المسار الزمني الموازي

### المرحلة صفر: خط الأساس — يومان

يُثبت سجل المستودعات والحسابات، وتُراجع الفروع المفتوحة وPull Requests، وتُسجل حالة Workflow الحالية، وحقوق الوصول، وحالة الأسرار. لا تُجرى تغييرات عن بُعد في هذه المرحلة.

**بوابة المرور:** صورة حالية قابلة للمراجعة لكل مستودع وحساب، مع تمييز ما هو مدمج وما هو Draft وما هو محلي.

### المرحلة الأولى: الحوكمة القابلة للتشغيل — 3 إلى 5 أيام

تُراجع مخططات الأحداث والموافقات، وتُثبت حالات `raw` و`review` و`approved` و`rejected` و`hold`، ويُراجع مسار `deterministic-gate`. كما تُحدد مسارات الإنشاء والقراءة والتعديل والنشر، ومن يملك اعتماد كل مسار.

**بوابة المرور:** كل فعل حساس له سياسة حتمية، وحالة موافقة، وإيصال، ومسار فشل آمن.

### المرحلة الثانية: CI ومراجعة التغييرات — 5 إلى 7 أيام

يُشغل فحص GitHub على Pull Requests بوضع غير إنفاذي أولًا، مع فحص الحتمية، fixtures السلبية، قابلية إعادة إنتاج النتائج، وسلامة artifacts. لا تُفعّل Branch Protection قبل ظهور اسم الفحص النهائي ونجاحه في تشغيل فعلي موثق.

**بوابة المرور:** نجاح Workflow فعليًا، وتوثيق اسم الفحص، ونتائج GH-01 وGH-02، وعدم وجود صلاحيات كتابة غير لازمة.

### المرحلة الثالثة: ربط الأتمتة التجارية — 5 إلى 7 أيام

تُسجل مهام Market Scanner وFit Classifier والتأهيل التجاري، وتبقى في `draft-only`. أي رسالة أو نشر أو ربط مالي يتحول إلى طلب موافقة مستقل، مع منع الإرسال التلقائي.

**بوابة المرور:** كل مهمة تجارية تنتج مسودة وسجلًا ومصدرًا، ولا تنفذ فعلًا خارجيًا دون اعتماد بشري.

### المرحلة الرابعة: إصدار Pilot الحوكمة — 5 إلى 7 أيام

تُربط عينة Pilot بالأصول والحقوق والإيصالات، وتُنشأ تقارير تغطية الأدلة، ثم تُراجع الفروع والمسودات المفتوحة. في نهاية المرحلة تصدر مذكرة Go/Hold للمسار التجاري فقط، ولا تعني تلقائيًا إطلاق النواة الحية.

**بوابة المرور:** قابلية إعادة التشغيل، اكتمال سلسلة المصدر، وتوثيق كل استثناء أو فجوة حقوق.

## 4. سياسة الفروع المقترحة

| نوع الفرع | الاستخدام | قيود التشغيل |
|---|---|---|
| `main` | الحالة المعتمدة القابلة للمراجعة | لا دفع مباشر من عمل ذكي دون مراجعة |
| `feature/*` | تطوير وظيفة أو عقد محدد | لا نشر خارجي |
| `chore/*` | حوكمة، توثيق، أدوات، إصلاحات تشغيلية | يحتاج فحصًا وإيصال تغيير |
| `experiment/*` | تجارب غير تجارية | لا وصول إلى الأسرار أو قنوات العملاء |
| `release/*` | تجهيز إصدار أو Pilot | يحتاج موافقة مالك وإيصال إصدار |

## 5. بوابة الحوكمة لكل نوع من الأفعال

| الفعل | الفحص الإلزامي | الموافقة المطلوبة |
|---|---|---|
| قراءة مصدر أو ملف | allowlist وProvenance | لا موافقة إضافية إذا كان ضمن النطاق المصرح |
| تعديل كود | Schema، tests، deterministic gate | مراجعة PR |
| تشغيل حساب أو أداة | هوية، أقل صلاحية، سجل تشغيل | اعتماد مالك النطاق عند الحساسية |
| إرسال رسالة أو نشر محتوى | مسودة، هدف، مستلم، نص، سياسة | موافقة بشرية صريحة |
| تغيير إعدادات GitHub | diff، target، rollback، receipt | موافقة صريحة قبل التنفيذ |
| ربط مالي أو تجاري | حقوق، مصدر، شروط، سجل مخاطرة | قرار مالك المشروع فقط |
| إصدار أو تفعيل حماية فرع | نجاح CI، اسم check النهائي، خطة تراجع | اعتماد مستقل عالي المخاطر |

## 6. التكامل مع الطبقة الإبداعية

تظل مساحة الإبداع مفتوحة للتوليد والتجريب. ولا تُفرض عليها دورة موافقات أثناء إنتاج فكرة أو مسار صوتي أو أصل بصري. عند اختيار أصل للإدخال إلى التجارة، يُنشأ له `creative_asset_ref` ويرتبط بالمصدر والحقوق والإصدار والنسخة المرشحة والمسار التجاري المقترح.

تبدأ الحوكمة عند نقطة الانتقال، لا عند لحظة الإبداع. أي أصل لا يملك مصدرًا أو حقوقًا أو وصفًا أو حالة استخدام يبقى في `creative_pool` ولا يدخل مسار الإعلان أو البيع أو الشراكة.

## 7. مؤشرات المسار

| المؤشر | الهدف |
|---|---:|
| التغييرات البرمجية القابلة للتتبع | 100% |
| حالات الفشل المعروفة التي تنتهي بـ`hold` أو `rights_gap` | 100% |
| الأسرار الموجودة خارج الكود | 100% |
| الأفعال التجارية الخارجية ذات موافقة موثقة | 100% |
| الإصدارات ذات receipt قابل للمراجعة | 100% |
| الأصول الإبداعية المنتقلة للتجارة مع سجل حقوق | 100% |

## 8. قرارات مؤجلة لا تُنفذ تلقائيًا

لا تُفعل حماية الفروع، ولا تُدمج Pull Requests المفتوحة، ولا تُنشأ Releases، ولا تُرسل رسائل، ولا تُربط حسابات مالية، ولا تُنقل أصول بين الحسابات، إلا بعد اعتماد مستقل يحدد الهدف والنطاق والنسخة وخطة التراجع.

**القرار التنفيذي المقترح:** اعتماد هذا المسار كطبقة تشغيل موازية، بحيث تكون الحوكمة إلزامية للكود والحسابات والأتمتة التجارية، واختيارية أثناء الإبداع، ثم إلزامية عند تحويل الأصل الإبداعي إلى أصل تجاري أو استثماري.
